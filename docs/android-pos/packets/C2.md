# C2 — Stubs that cannot do the job must refuse, not report success

## Context

`src/renderer/android-pos/shim/stubs.ts` is the Android implementation of the
`window.electronAPI` surface that the shared renderer calls. Where Android cannot
do something, the established discipline in that file is to **refuse with a
message**, not to fake success — several methods already do exactly that, with
comments explaining why (`cancel`, `deleteLocal`, `refund`, and
`printFiscalReceipt`, which never claims a receipt was printed because a false
fiscal claim is a legal problem).

Four methods break that discipline. Each returns success unconditionally while
doing nothing.

## Your task

### 1. `mutate` — the worst one

Currently:
```ts
mutate: async () => ({ success: true, localOnly: true }),
```

This is the order **void / edit** path. The renderer calls it from
`src/renderer/components/pos/OrderHistoryModal.tsx` (`runMutation`), and the
`ensureMirrored` gate above it returns `true` immediately for local orders, so an
unsynced sale reaches this method for real. The UI then renders
"Local order updated" and treats a void as done, while the order stays
`COMPLETED` and still syncs to the backend as a real sale.

Verified live on a device: calling it with a **non-existent order id** still
returns `{success: true, localOnly: true}`.

Make it refuse, in the same shape and style as the neighbouring `cancel` /
`deleteLocal` / `refund` refusals. The message must name the working alternative,
because the reader is a cashier with a customer waiting:

- An unsynced local order **can** be removed — the Order History UI already shows
  a working "delete local" action for it (`canDeleteLocal` in
  `OrderHistoryModal.tsx`, backed by `deleteLocalUnsynced`, which restocks).
- A synced order must be corrected at the Windows counter.

Do **not** implement a real local void here. That is a separate decision, out of
scope for this packet.

### 2. `reconcileFiscalAttempt`

Currently `async () => ({ success: true })`. The Windows handler
(`pos:fiscal:reconcile` in `src/main/modules/pos.module.ts`) refuses when there is
no unresolved fiscal attempt for that order, and refuses again if the resolution
cannot be persisted.

Android has no fiscal attempt journal, and `getReconcilableFiscalAttempt` always
returns `attempt: null`, so today the UI never offers the action — but a bare
success here is a mine waiting for the day it becomes reachable. Make it refuse.

### 3 & 4. `hold.create` and `hold.remove`

Both currently return a bare `{ success: true }`. Their siblings
`hold.createCurrent` and `hold.recall` already return
`{ success: false, error: 'desktop-only' }`. `hold.create` has no renderer caller
today; `hold.remove` makes discarding a held cart look like it worked. Bring both
in line with their siblings.

## Do NOT change

Any stub that already refuses correctly. Any stub whose unconditional success is
genuinely correct for Android (single-window `window.*` operations, `seedDemo`,
and the `withTransport(...)` synthetic fallbacks that only fire when no transport
is injected). If you are unsure whether one qualifies, leave it and say so in
your report.

## Tests you must add / update

1. New file `tests/android-refuse-not-lie.test.ts`:
   - For each of the four methods above: assert `success === false` and that
     `error` is a non-empty string.
   - For `mutate`, additionally assert the error text mentions the working
     alternative (delete-local for unsynced orders), so a future reword cannot
     quietly drop the guidance.
   - Add an **anti-rot guard**: a hard-coded list of the method paths that are
     allowed to return unconditional success, and a test that walks the built
     stub surface and fails if any method outside that list returns
     `{success: true}` when called with obviously invalid arguments. Keep the
     list short and comment why each entry is on it.

2. `tests/android-shim.test.ts` pins these literals on purpose — its header says
   "changing one here is a contract change — update S1 + the test together".
   Update it in the **same commit**.

3. If `docs/android-pos/SHIM_CONTRACT_S1.md` documents these four literals,
   update those lines too.
