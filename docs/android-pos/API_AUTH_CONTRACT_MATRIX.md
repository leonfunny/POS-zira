## Non-negotiable Android identity and payment rules

- Android is an authenticated staff client. Its native session broker sends `Authorization: Bearer <staff access JWT>`; raw refresh tokens remain outside WebView JavaScript. The JWT tenant is validated against an active user and salon (`backend/src/modules/auth/strategies/jwt.strategy.ts:95-136`) and exposed as `userId`, `salonId`, role, and session (`jwt.strategy.ts:191-198`).
- Android must not store or transmit a salon-wide print-agent `pa_` key, must not send `x-print-agent-api-key`, and must not call `POST /api/v1/print-agent/connect`. Those routes are explicitly Windows print-agent routes (`backend/src/modules/print-agent/controllers/print-agent.controller.ts:72-100`).
- A non-secret installation ID such as `X-POS-Device-Id` is correlation only until a terminal-registration ADR is approved. It is not authentication and cannot select a tenant.
- Android runtime order writes are **CASH-only**. CARD, BLIK, TRANSFER, and any split containing an electronic tender remain disabled until provider authorization/capture and backend validation are implemented. The current backend otherwise marks every non-credit tender set paid (`backend/src/modules/b2b/services/b2b-pos.service.ts:887-935`).
- Deliberate offline selling, remote print, and fiscal actions remain disabled. No row marked `BLOCKED` or `CONDITIONAL` is permission to wire a runtime call.

The backend authenticates all routes globally unless `@Public()` opts out (`backend/src/app.module.ts:294-304`; `backend/src/modules/auth/guards/jwt-auth.guard.ts:13-32`). Therefore a route below described as Staff JWT is protected even when its controller only declares role guards.

## Authoritative retry rules for shared application code

1. A retryable command is persisted before network dispatch with immutable tenant, actor, device, command ID/idempotency key, payload, and payload hash.
2. `400` means the staged command is invalid and stops. `401` pauses for re-auth without rewriting the command. `403` stops and surfaces role/feature/tenant denial. `409` stops unless that exact route documents a cursor reset; never treat every 409 as success.
3. Network timeout, disconnect, and `5xx` are ambiguous writes. Reconcile through the exact route named above; never create a new key or mutate payload.
4. Catalog failure preserves the last good snapshot. Empty data is authoritative only in a successful response whose cursor/snapshot protocol says it is complete.
5. Print `TIMEOUT`, `SENT`, `PRINTING`, and `UNCERTAIN_AFTER_PRINT` are sticky unknown/in-flight states. They are not failed and are never automatically replaced.
6. Android code must not infer tenant from `X-Salon-Slug`, device from an arbitrary header, staff from DTO fields, payment capture from tender name, or fiscal outcome from an HTTP timeout.

## Exit gate for this provisional matrix

This matrix becomes implementation-authorizing only after every P0 is closed in committed canonical backend source, deployed through the guarded backend lane, verified in the production built artifact, and the decisions in the companion register are owner-approved. Until then, allowed work is synthetic contract testing and read-only catalog discovery only.
